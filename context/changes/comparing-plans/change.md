- **N-plan comparison is architecturally free** — `analyzePlan` has zero pairwise coupling and `bench/plan-report.ts` already renders N side-by-side columns. Model as `plans[]` from day one; ship the UI comfortable at N=2–4 (the scoreboard is per-cohort, so N plans = 2N columns). *(Originally `plans[] + baselineId`; the zero pairwise coupling noted here is exactly why the `baselineId` half turned out to be unnecessary.)*
- Hard invariants inherited from the analyzer, to carry into React: **feature vector, never a score** (no "Plan A wins"); **no slot count without completeness beside it**; render `emptyDays` beside day-edge metrics; render catalog `warnings` beside the numbers.

## Implementation notes (2026-07-14)

- **Implemented, all 6 phases** (`5c1aed3`, `20734c1`, `29c599a`, `43b77f6`, `5f823da`, `fc1d0b3`). Full `/verify` gate green; 33/33 e2e; 112/112 integration. The UI's numbers were cross-checked against `ANALYZE_PLAN_A=<golden> pnpm analyze:plans` and agree **digit-for-digit** (13 metrics × both cohorts, plus the Chemistry overlap annotations) — they now share one loader and one metric catalog, so that is a property, not a coincidence.
- **Progress row 6.4 (CI `e2e` job passes on the PR) is intentionally left open** — the author chose to close out locally rather than push a branch/PR. `/10x-archive` will surface it as an informational warning. Everything 6.4 would confirm has been verified locally against the real workerd preview.
- **The `bench/` → `_pages` ESLint guardrail has a sharp edge worth knowing.** The obvious spelling — `group: ["@/_pages/*", "!@/_pages/plan-comparison/api"]` — silently permits *nothing*: ESLint matches these gitignore-style, and a `!` cannot re-include a path whose **parent directory** an earlier pattern excluded. The slice-root ban therefore lives in `paths` (exact match, no subtree semantics) and the carve-out in its own group. Verified against the real matcher and against a deliberate violation, not assumed.
- **`api/index.ts` is deliberately narrow and must stay so.** It is `bench/`'s entire contract with `src/`. `load-comparison` is *not* re-exported from it: that module value-imports `@/entities/timetable` for `analyzePlan`/`verifyGeneration`, and the entity barrel re-exports `CollisionDetailsDialog` (a React component) — so exporting it there drags all of `shared/ui` into `pnpm analyze:plans`, a Vitest **node** run. The Astro route imports it by direct path instead. This regressed once mid-implementation and was caught by walking the barrel's import graph; re-run that walk if the barrel ever grows.
- **Known local-stack flake, not a code defect.** The integration lane intermittently fails an *unrelated* suite with `An invalid response was received from the upstream server` — a 502 from the local Kong/PostgREST, whose logs show `Warp server error: Thread killed by timeout manager`. It is request-load saturation against a long-running local `supabase_rest` container: this change's loader fires ~15 concurrent queries per plan, which tips it over. **Restarting the container clears it** (`docker restart supabase_rest_<project>`), after which the suite ran 4/4 and then 3/3 green. CI boots a fresh stack per run, so it should not see the stale-container condition.

## Post-ship redesign — selection on the hub, no baseline (2026-07-14)

The author used the shipped UI and rejected two things. Both were right, and the second was not a taste call — it was a defect of concept.

- **The in-page plan picker is gone.** It was client state driving SSR-rendered numbers: changing the selection re-rendered the picker but not the columns, so the page could show one selection and one set of measurements that disagreed with it. Selection now happens on the `/plans` hub via row checkboxes — the same multi-select the students catalog already established — and a Compare button appears once two are ticked. The compare page renders exactly what the URL names; the only way to change it is the "Change selection" link back to the hub. With no client state left, the page also dropped `client:load` entirely and shipped **zero JS**. *(**`client:load` was later restored** for the metric-help popovers — see [Fifth pass](#fifth-pass--the-metrics-explain-themselves-2026-07-14). The guarantee is unchanged and does not depend on hydration: it comes from the page holding no state that **chooses what is measured**. A popover's open/closed state cannot reach the numbers.)*
- **The baseline is gone, and so are the deltas.** The author's question — *"the experts like to compare two or more plans without a clear indication of which is a baseline"* — exposed that the measurements never needed one. `analyzePlan` has **zero pairwise coupling**: every metric is a property of one plan alone, which is exactly why `bench/plan-report.ts` prints N columns and no deltas. Only the delta column needed a reference, and a delta needs a *direction*, not a privileged plan. Calling one plan "the baseline" was the weighted-scalar tier-bleed lesson wearing a different hat — it smuggles back "this one is the truth" into a tool whose whole rule is *it reports; it never judges*. The page is now exact bench parity: the columns side by side, and the expert does the judging. `deltas.ts` and `PlanPicker.tsx` are deleted; `MetricRow` no longer exposes a numeric reader, so nothing downstream *can* subtract one row from another.
- **What still needs an order, and why that is not a baseline.** The drift banner describes a catalog *relative to* the first-listed plan ("The catalog is not identical to **Expert**'s…") because a comparison is inherently directional. The order is simply the hub's row order. The report's sides are named `reference`/`other`, never `baseline`. No number on the page is measured against another. *(The banner's wording was simplified further in [Third pass](#third-pass--the-drift-banner-stops-enumerating-2026-07-14); the direction survives, the enumeration does not.)*
- **The hub builds the URL the compare page parses, across a slice boundary steiger will not let them share.** That query-string shape is an unenforced contract between `plans-list` and `plan-comparison`; the e2e spec now drives the real checkboxes rather than a hand-built URL, so a divergence fails the suite.

### Second pass — the completeness prose out, the worst cases linked (2026-07-14)

- **The completeness annotation list is gone.** It restated in prose what the scoreboard's own first two rows already say in numbers. **The invariant it encoded is not gone**: `UNPLACED HOURS` and `OVER-PLACED HOURS` are rows 1 and 2 of the cohort scoreboard, above every slot count, per plan per cohort — that adjacency is what the invariant actually demands, and a unit test now pins the ordering rather than the prose. What was lost is the *which course* detail ("Maths HL −2h"); the cohort-level shortfall itself still renders. If a slot count ever moves into a section carrying no hour accounting, the annotation has to come back with it.
- **The worst-teacher / worst-student rows printed a raw UUID.** `format.extreme` rendered `${entry.key}: ${value}`, and the analyzer's key *is* the teacher/student id — so the Board-wide table read `9f3a…: 42`. Meanwhile the per-plan card below resolved the same fact to a name. The table now resolves the name (the loader already carries the id→natural-key maps for the fingerprint, so it costs nothing) and the duplicate card block is deleted.
- **…and that discarded id is exactly what the entity routes are keyed by.** So the cell links: `/plans/<planId>/teachers/<teacherId>` and `/plans/<planId>/students/<studentId>`, per column, so the link lands in the plan whose column you clicked. The number says *who*; the linked timetable says *why*. A link is not a judgement — the no-verdict rule is intact, and a unit test pins that these are the only two linked rows (a link on a slot count would promise a drill-down that does not exist).
- `model/annotations.ts` → `model/extremes.ts`, since the annotation half is what left. `MetricRow.read` now returns a `MetricCell` (`{ text, href? }`) rather than a bare string, which keeps the no-delta guarantee structural: a row still exposes no number for anything downstream to subtract.

### Third pass — the drift banner stops enumerating (2026-07-14)

- **The per-category counts are gone, and so is the structured diff that produced them.** The banner said "4 courses removed, 9 courses changed, 1 teacher added, 61 students added, 61 students removed, 652 choices added, 714 choices removed, 125 availability cells removed" for two genuinely different plans. **This reverses the original design note** ("it NAMES the drift rather than merely announcing it"), and the author is right to reverse it: a count cannot answer the only question it raises — *which* course, *which* student — and answering that takes a second table, not a banner. A count nobody can act on is noise dressed as diligence.
- **What the banner keeps is the actionable half**: the catalogs are not one-to-one, *and which metric families that spoils* (catalog-dependent ones are counting different populations; board shape, daily load, week symmetry, adjacency and spread still compare). That sentence is what stops a reader trusting the wrong number, which was the banner's actual job — the enumeration never was. The `incomparable` tier still names both grid shapes (`5×10` vs `5×8`), because two shapes is not a wall of numbers and it says exactly what broke.
- **`model/catalog-diff.ts` (+ tests) deleted — ~150 lines.** With no counts to render, the tier rests on the two facts it always actually rested on: `catalogEqual` straight from the natural-key fingerprint, and `gridEqual` from the two board shapes. `DriftReport` carries `grid` instead of `diff`. The fingerprint is now the **whole** drift detector, so the integration test that adds one student — the smallest catalog change the product has — is what stands between a silent banner and a reader comparing two different student bodies as if they were one.

### Fourth pass — the frozen pane comes out (2026-07-14)

- **The sticky header row and the bounded-height container are gone** (`d1a80c4`). The longest section is 18 rows, which fits a desktop viewport, so the vertical freeze was solving a problem the page does not have. The tables now render at full height and the page owns the scrolling — verified on the real preview (`scrollHeight === clientHeight`, so the container no longer scrolls at all).
- **The metric-label column is still frozen, deliberately — and that is not an oversight.** It is a *horizontal* concern, unrelated to row count: a cohort section is 2N columns wide, so at three or four plans it scrolls sideways and the row label would slide off the left edge, leaving a column of numbers naming nothing. It rides the table container's own `overflow-x-auto` and needs no height bound.
- **The `max-h` trap is kept in the docblock as a warning, not a rationale.** The DS `Table` wraps itself in `div[data-slot=table-container]` with `overflow-x-auto`, and per the CSS overflow spec a non-`visible` value on one axis computes the other to `auto` — so that div is *already* a scroll container on both axes, with no height constraint. Anyone re-adding `sticky top-0` without also setting an explicit `max-h` gets a header that resolves against that div and **silently does nothing**: perfect in a short table, broken in a long one.

### Fifth pass — the metrics explain themselves (2026-07-14)

- **`MetricHelp` popovers** (`10b77b6`, `a42568b`), on the blocks whose labels do not explain themselves: the Distributions section, per-person spread, mirrored cells, the time-of-day gradient, and **all six cross-cohort rows**. These figures came out of the analyzer, not out of a vocabulary anyone shares — "span efficiency" and "cohort-pure teacher-days" are not phrases a reader has met — and a number nobody can interpret is indistinguishable from a number nobody should trust.
- **The copy is written from the analyzer's source, not from the metric names**, and that is load-bearing rather than fussy. Two cases would otherwise be read backwards:
  - **`lateFinishes` is `periods − last`** — the periods remaining *after* a student's last lesson. So **`0` means they finish in the FINAL period**, and a large number means they go home early. The name says the opposite of the number. The popover states the inversion outright and a unit test pins that sentence, so the copy cannot drift back to the intuitive-but-wrong reading. **See the deferred follow-up below — the real fix is the metric's name.**
  - **A cohort switch is a step between *consecutive* lessons**, read per teacher-day-**week** lane. `DP1, DP1, DP2` is one switch, not two; and a teacher in DP1 in week A and DP2 in week B, in the same cell, has not switched at all (the alternating-week fixture). "Seamless" then means the switch lands in an adjacent period rather than across an idle gap — which is why there are two rows and not one: the count says how *often* a teacher changes cohort, the share says what it *cost* them.
- **It explains; it still does not judge.** No thresholds, no good/bad. "Shared subject-edition days" gives the case on both sides (one preparation covers two lessons; the teacher repeats the same material twice in a day) and leaves the call to the reader.
- **Row help is `string[]`, not JSX — a constraint, not a style choice.** The scoreboard is assembled server-side and crosses the island boundary, so a row's help must serialize; that is also why `metric-catalog.ts` stays `.ts` (JSX-free), per the repo's `.tsx`-only-for-JSX rule. Consequence for any future request: row help can be paragraphs but **not** bold/italic/links. The Distributions popovers, written directly in the component, are free to use markup. Enriching row help means a richer serializable shape, not inline JSX.
- **`client:load` is back on `/plans/compare`.** See the correction in the Post-ship redesign entry above: it does **not** reopen the picker bug. That bug was client state *selecting the data*; a popover's open/closed state cannot reach the numbers. The rule is recorded at both ends (route and component): **no client state on this page may choose what is measured.**

## For the reviewer — deliberate reversals, not regressions (2026-07-14)

Six post-ship commits (`8f62ffe`, `4f0c59f`, `d1a80c4`, `10b77b6`, `3b1d9da`, `a42568b`) came out of an author feedback loop on the shipped UI. **Several of them reverse design notes written earlier in this very document**, so a review that reads the old note against the new code will read them as regressions. They are not. Each reversal, and why it stands:

| Reversed | The old note said | Why it was wrong |
| --- | --- | --- |
| **Baseline + deltas** (`8f62ffe`) | "delta needs a baseline plan" | `analyzePlan` has zero pairwise coupling — every metric is a property of one plan alone. Only the delta needed a reference, and a delta needs a *direction*, not a privileged plan. "The baseline" was the weighted-scalar tier-bleed lesson wearing a different hat. |
| **Completeness prose** (`4f0c59f`) | "a slot count never renders without its cohort's hour accounting **beside it**" | The invariant holds — `UNPLACED HOURS` / `OVER-PLACED HOURS` are rows 1–2 of the same table, above every slot count. The prose *restated* the numbers; it was never the thing enforcing the invariant. **If a slot count ever moves into a section carrying no hour accounting, this must come back.** |
| **Frozen header** (`d1a80c4`) | an elaborate docblock on bounding the container | 18 rows fit a desktop viewport. The failure it guarded against was real but the page never had it. |
| **Drift enumeration** (`3b1d9da`) | "it NAMES the drift rather than merely announcing it" | A count cannot answer the question it raises — *which* course, *which* student — and answering that takes a second table, not a banner. A count nobody can act on is noise dressed as diligence. |
| **Zero-JS page** (`10b77b6`) | "ships zero JS: structural, not a convention" | The guarantee comes from holding no state that *chooses what is measured*, not from shipping no JS. Popover state cannot reach the numbers. |

**The invariants that did NOT move, and must not:**

- **It reports; it never judges.** No composite score, no ranking, no better/worse, no delta, no pass/fail threshold — not in a cell, not in a colour, not in the help copy. `MetricRow` exposes no numeric reader, so nothing downstream *can* subtract one row from another: the rule is enforced by the type, not by memory. The two linked cells are links, not verdicts.
- **A slot count never renders without its cohort's hour accounting.** Now carried by row order inside the table, and pinned by a test.
- **`emptyDays` renders beside the day-edge metrics**, and catalog `warnings` render beside the numbers (`VerdictBlock`). Unchanged.
- **The natural-key fingerprint is the whole drift detector** — more so than before, since the structured diff is gone. A clone must produce **no** banner (e2e), and one added student must produce one (integration). Those two tests are the feature.

## Deferred follow-ups

- **`lateFinishes` is misnamed in the analyzer** (`entities/timetable/model/analysis/student-lens.ts`). It computes `periods − last` — periods remaining *after* the last lesson — so a *low* value is a *late* finish. The comparison page papers over this with help copy; the honest fix is to rename it (`periodsAfterLastLesson`, or invert it) in the analyzer and update the bench, which is out of scope for a UI change. Until then, **any new surface reading this field will get it backwards.**
- **A `co-teaching` e2e flake** was observed once in a full-suite run and passed in isolation and on re-run; unrelated to this change (it touches teachers/courses only). Recorded so it is not attributed here if it resurfaces.
