## Notes

<!-- Free-form notes for this change: links, ad-hoc context, decisions that don't belong in research/frame/plan. -->

- **2026-07-07 — Format decision: XLSX over CSV.** Resolves PRD Open Question #3 in-scope with a format change: the export ships as a styled `.xlsx` workbook, not the historically-specified "master-grid CSV". Rationale: rich, better-structured content — CSV cannot represent the enriched model (two cohorts, co-teaching, bi-weekly week tags, colors, merged cells) in one readable sheet. Content requirement carries over unchanged from `prd.md:380-381`: master grid distinguishing both cohorts, representing co-teaching + bi-weekly weeks. Follow-up: reflect this in `prd.md` Open Questions when the change lands.
- **2026-07-07 — Workbook scope: mirror the board focus modes.** The export mimics the existing focus/view switcher: the user chooses which view to export — **combined**, **dp1**, or **dp2** — and the file is prepared for that view. Same surfaces as `CohortSwitcher` (`/plans/{id}?focus=<combined|dp1|dp2>`); the export UI should offer this choice (sensible default: the currently active focus). Per-teacher / per-student sheets are NOT in scope for this change.
- **2026-07-07 — Fidelity principle: mirror the rendered view.** The exported file should be as close as possible-and-reasonable to what the user sees on screen. Concretely, the sheet reproduces the board's layout: period rows × day columns; in **combined** the sheet arranges the two cohorts the same way the combined view renders them — each day header spans two cohort sub-columns (DP1 | DP2) with a cohort sub-label row beneath (see `PlannerGrid.tsx:79-96`; maps to xlsx merged header cells). Focus exports (dp1/dp2) are the single-sub-column variant. This principle also guides the remaining styling details (subject colors, week a/b tags, optional markers, break bands): include them where the xlsx medium supports it reasonably; don't over-engineer beyond what the screen shows.
- **2026-07-07 — Parked/shelf bundles: out of scope.** The export covers the placed board grid only; shelf/parked bundles (unscheduled courses) are omitted from the workbook.
- **2026-07-07 — Source of truth: live board state.** The export captures the **live in-session board state** (including unsaved optimistic edits) — "export what you see" — not a server-side re-read of persisted rows. This commits the implementation to **client-side generation** in the board island (Blob download from the store state), which also makes the Cloudflare CPU/plan question moot and keeps the Worker bundle untouched.
- **2026-07-07 — Design for future server-side reuse (batch export).** Client-side generation ships now, but the workbook-building logic must be structured for reuse in a possible future **batch export** (e.g. one xlsx per student / per teacher, generated server-side). Implication for the plan: keep the grid→workbook assembly a **pure, runtime-agnostic transform** (plan data in → `write-excel-file` schema/rows out), framework-free and importable from both a React island and a Worker route; only the final "download a Blob" step is browser-specific. `write-excel-file`'s `universal` entry runs on workerd, so the same dependency serves both paths. Placement of the pure module should anticipate cross-slice reuse (batch export would be a different slice — consider `entities/timetable` or `shared/lib` rather than burying it in `_pages/plan-detail/model/`).
- **2026-07-07 — Scope extension: per-cohort subject roster sheet(s).** Post-plan-review request: besides the timetable grid, each exported workbook carries **one "subjects" worksheet per exported cohort** ("DP1 subjects" / "DP2 subjects" in combined; the one cohort's tab in focus) listing **all catalog subjects** (placed or not) with their assigned teachers and students as resolved names, plus weekly hours. Data is already island-hydrated (`PlannerBoardProps.catalog` = `GroupingCourse[]` with `teacherKeys`/`studentKeys`; `teacherNames`/`studentNames` maps); `write-excel-file` supports multi-sheet natively (array of sheet descriptors). Built as a second pure transform (`buildRosterSheet`) beside `buildTimetableSheet`. The earlier "no per-teacher/per-student sheets" decision stands — it excludes per-person *timetable grids*, not this flat roster list.
- **2026-07-07 — Cloudflare subscription: paid plan** (for the record). Workers CPU budget is 30 s/request (configurable to 5 min) and the script-size limit is 10 MB gzipped — so the future server-side batch path is realistic without infra changes.
- **2026-07-08 — Grid fidelity refinement: one cell per course, vertical sub-rows (supersedes the newline-join + single-occupant-fill rules).** Post-implementation feedback: match the web board's chip layout and get correct per-course colors. `buildTimetableSheet` now renders each period as a **block of sub-rows** — one per stacked occupant — so **every course occupies its own cell and keeps its own subject-color fill** (the earlier plan rules "join occupants with `\n` in one cell" and "fill only single-occupant cells" are retired; a bundle's courses no longer share a neutral cell). A period is as tall as its busiest day×cohort cell; lighter cells get empty filler cells beneath their courses. The **time-range row header is one cell that `rowSpan`s the period's sub-rows** (vertically centered), per the "time range cell can span as needed" request. Verified against real `write-excel-file@4.1.1` output: `mergeCell A3:A4` (time rowSpan) + three distinct subject fills for a 2-course bundle, no "unreadable content" error. Uses the library's documented rowSpan rule (each hidden cell below the span is `null`; the library copies the origin border onto them).
- **2026-07-08 — Border weighting for structure.** Feedback follow-up: stronger separators so column/period boundaries read clearly. Over the thin light-gray internal grid (`#D1D5DB`), a **medium** darker line (`#4B5563`) closes each **day column** and each **period block** (and the header block's bottom + the frozen time-label column's right), while a **thin** darker line marks the **cohort split** (DP1|DP2) within a day. Implemented with per-side border overrides (`rightBorder*`/`bottomBorder*`), which the library resolves over the all-sides `borderStyle` via `||` fallback; the rowSpanned time header's strong bottom is carried onto the period edge by the merge. Verified in real output. Weights later tuned lighter by the author (grid `hair`, separators `thin`).
- **2026-07-08 — Break bands: filled hatch (echo of `bg-period-break`).** Feedback follow-up: the P2/P5 spacer rows were blank and easy to miss. They now carry a **patterned fill** mirroring the board's faint diagonal hatch — a light-grey base (`#F3F4F6`) under `lightUp` diagonal hatch lines in mid grey (`#9CA3AF`) — and close with the **same bottom rule as the time-range header** (so the band is framed like a period block). Uses `write-excel-file`'s pattern-fill mapping (`fillPatternColor` → `fgColor` lines, `backgroundColor` → `bgColor` base; both required per `hasFill`). Verified in real output: `<patternFill patternType="lightUp"><fgColor rgb="FF9CA3AF"/><bgColor rgb="FFF3F4F6"/></patternFill>`.
